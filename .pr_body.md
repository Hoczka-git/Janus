## Summary

Add approval request handling to `dispatch_completion` for actions requiring approval per policy. When the enforcement gate returns APPROVAL_REQUIRED, an ApprovalRequest is generated with full context (action, entities affected, risk level, rationale), presented to the user via CLI prompt, and execution resumes on approval or aborts on denial/deferral.

## New Components

- `src/janus/models/policy.py`: Phase E policy models (PolicyAction, RiskLevel, ImpactLevel, PolicyDecision, ClassificationCategory, PolicyRule, Policy, PolicyDecisionRecord, create_default_policy)
- `src/janus/models/policy_p1.py`: P1 policy models (PolicyVerdict, PolicyRule, PolicyDecision, ApprovalRequest, ApprovalResponse, ApprovalRecord)
- `src/janus/services/policy_engine.py`: PolicyEngine with YAML-driven rules, classify() interface, and audit logging
- `src/janus/services/enforcement_gate.py`: Pre-execution enforcement gate that calls PolicyEngine.classify() before any action executes
- `src/janus/exceptions.py`: PolicyDenialError, PolicyApprovalRequired
- `src/janus/cli/approval.py`: format_approval_prompt() utility

## Integration

- `dispatch_completion()` now evaluates the enforcement gate before dispatch
- APPROVAL_REQUIRED triggers approval request flow (build -> present -> resume/abort)
- USER_ONLY blocks immediately without approval prompt
- Policy models exported from `models/__init__.py`
